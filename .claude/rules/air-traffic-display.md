### Page 5 — Air Traffic Display (ATD)

A live OSM map page with nearby-aircraft tracking against OpenSky's `/states/all`, built in phases per `AIR_TRAFFIC_DISPLAY_PLAN.md` (kept at the repo root — read it for the full phase-by-phase rationale). **Phases 1–4 are done** (page skeleton, location-centered map, OAuth2 token + data source, aircraft model + on-map markers), plus **part of Phase 6** (the DMS position + city/temperature/date/time overlay bars, added ahead of the rest of that phase by explicit request); **Phases 5, 7, 8 and the rest of 6 are not** (no marker motion animation, no traffic-count readout, no "Traffic Unavailable" UI, no dedicated performance pass beyond the visibility gating described below). Every piece has one job, matching the rest of the codebase's "independent providers, cross-wired only where needed" style — the dependency chain is `AirTrafficPage → FlightTrackerProvider → FlightDataSource (interface) → OpenSkyFlightSource → OpenSkyTokenManager`, with `AircraftListModel` sitting off to the side as the thing `FlightTrackerProvider` feeds and `TrafficMap` reads from.

**QML layer** — `utilities/AirTrafficPage.qml`, `TrafficMap.qml`, `AircraftMarker.qml`, `MapStyleMenu.qml`, `ZoomButton.qml`, `CenterCrosshair.qml`, `CoordinateBar.qml`, `StatusBar.qml`:

- **`AirTrafficPage.qml`** — composition only. Instantiated in `main.qml` (`swipeView`'s 6th child) with `currentLatitude: location.latitude` / `currentLongitude: location.longitude` / `currentCity: location.city` / `currentTemperature: weather.currentTemperature` / `timeProvider: timeDate` (all plain property bindings — no new fetch logic, reuses `LocationProvider`/`WeatherProvider`/`TimeDateProvider` as-is; `timeProvider` is the one exception to "primitives only," passed down as the whole object since it ticks every second — `AirTrafficPage` itself picks primitives off it for `StatusBar`, see below). Since `LocationProvider` defaults both lat/lon to `0.0` until its first successful `ip-api.com` fetch, `hasLocationFix` (`currentLatitude !== 0 || currentLongitude !== 0`) gates whether `TrafficMap.center`/`CoordinateBar` get the real fix or a stable `placeholderCenter`/"Acquiring position…" — this fallback is a named property, not a self-referencing binding on `trafficMap.center`, because `cond ? X : trafficMap.center` evaluates to an invalid `(0,0)` `QGeoCoordinate` on first evaluation rather than any sensible fallback (a real bug hit once during development). It also instantiates `FlightTrackerProvider` directly (`id: flightTracker`, see below) and binds its `active` property to `root.SwipeView.isCurrentItem` — the attached property Qt Quick Controls puts on every direct `SwipeView` child — so OpenSky polling and the 30s refresh timer both pause automatically the instant the user swipes away, rather than running (and burning API credits) in the background forever.
- **`CoordinateBar.qml`** — full-width bar pinned to the page's top, showing the live fix as DMS (`D°MM'SS"N   D°MM'SS"E`) rather than raw decimal degrees. Purely presentational (`latitude`/`longitude`/`hasFix` in, nothing else) — `formatDms()` handles the rounding-carry edge cases (a seconds value that rounds up to 60 carries into minutes, which can itself carry into degrees) explicitly rather than ever displaying `"60""`. Safe to sit under `main.qml`'s transparent 40px window-drag `Rectangle`, since it's text-only and needs no mouse events.
- **`StatusBar.qml`** — small rounded translucent panel, bottom-left: city + temperature on one line, date + time on the next (two lines, not one, because `TimeDateProvider.date`'s `"dddd, MMMM d, yyyy"` format is too long to share a single 320px-wide line with city/time/temperature). In `AirTrafficPage.qml`, anchored `right: controlColumn.left` (not `parent.right`), the same "anchor to controlColumn, not a specific button" approach `MapStyleMenu` already uses, so it never runs under the zoom/style buttons. Deliberately a flat translucent `Rectangle`, not a `FastBlur` glass panel like the Weather page's — blurring would mean sampling the live, panning/zooming `Map` every frame instead of a static background image, a per-frame cost this app can't spend on a Pi Zero 2 W.
- **`TrafficMap.qml`** — owns the `Map` + `Plugin { name: "osm" }` + camera (`center`/`zoomLevel`) + tile disk cache + `mapStyle` ("standard"/"dark"), **and** (Phase 4) hosts a `MapItemView { model: aircraftModel; delegate: MapQuickItem { sourceItem: AircraftMarker {...} } }` inside the `Map` — `aircraftModel` is supplied by the caller (`AirTrafficPage`, from `flightTracker.model`) and this file never constructs one itself. Aircraft markers had to live here rather than being composited on top by `AirTrafficPage` because Qt Location only positions a `MapQuickItem` correctly when its `MapItemView` is a direct child of the `Map` it belongs to. Each delegate centers itself on its coordinate via `anchorPoint: Qt.point(sourceItem.width/2, sourceItem.height/2)` (the default `(0,0)` anchor would offset every marker down-and-right of its real position).
- **`AircraftMarker.qml`** — one aircraft symbol (`Resources/traffic/aircraft.svg`, nose-up/north-zero so `heading` maps straight to `rotation` with no offset), not a dot, matching real ATC/traffic-display convention. Ground traffic is dimmed (`opacity: 0.55`) rather than hidden. Purely visual — no idea where its data comes from. **No position/rotation `Behavior` yet** — a row's `heading`/`onGround` (and, transitively, its marker's `coordinate` via the delegate binding) currently *snap* to each ~30s update rather than animating smoothly between them; that's Phase 5, not yet implemented.
- **`CenterCrosshair.qml`** — fixed "+" at the map's center representing the user's position. Never moves; the map recenters under it instead.
- **`ZoomButton.qml`** — generic 40×40 round button (symbol + `clicked()` signal only, no zoom/style knowledge of its own). Reused directly for both the +/− zoom controls and every button inside `MapStyleMenu.qml` — no separate button component was written for the style picker.
- **`MapStyleMenu.qml`** — horizontal strip of `ZoomButton`s (one per entry in its `styles` list) that fans out to the left of a toggle button. Emits `styleSelected(id)`; knows nothing about how a style actually renders.

**C++ backend** (flat at repo root, alongside `TimeDateProvider`/`LocationProvider`/`WeatherProvider` — registered the same way in `main.cpp`, `qmlRegisterType<FlightTrackerProvider>("FlightTracker", 1, 0, "FlightTrackerProvider")`, and only ever instantiated from QML, in `AirTrafficPage.qml`):

- **`FlightTrackerProvider`** — the one type QML sees; pure orchestration, no HTTP/JSON of its own. Owns a 30s repeating `QTimer` (only runs while `active` is true), converts `currentLatitude`/`currentLongitude` + `searchRadiusKm` (default 1000, i.e. effectively unbounded for a hobby deployment — the plan's "50km" default was widened) into a `GeoBoundingBox` per request, and merges results into its owned `AircraftListModel` via `upsert()`. On `requestFailed`, it updates `status`/`errorString` (`"Ok"` / `"Unavailable"`) but **deliberately never touches the model** — the last known aircraft positions simply stay on screen instead of the map going blank on a transient network blip. Also re-fires `refresh()` immediately (not just on the next timer tick) whenever `active` flips true or the position changes, so becoming visible or getting a location fix doesn't wait up to 30s for the first paint.
- **`FlightDataSource`** — abstract interface (`requestStates(GeoBoundingBox)` + `statesReady`/`requestFailed` signals). `FlightTrackerProvider` holds this type, not `OpenSkyFlightSource*` directly, so swapping data providers later touches nothing above this line (classic dependency inversion).
- **`OpenSkyFlightSource : FlightDataSource`** — the only concrete implementation today. Builds the `/states/all?lamin=…` GET, attaches a Bearer token from its own internal `OpenSkyTokenManager`, and parses the response into `QVector<Aircraft>` via a static, side-effect-free `parseStates()`. A request that arrives before a valid token exists is stashed (`m_pendingBox`/`m_hasPendingRequest`) and resumed from the token manager's `tokenReady()`/`tokenError()` signals, since token acquisition is itself async.
- **`OpenSkyTokenManager`** — OAuth2 client-credentials lifecycle only (OpenSky dropped Basic auth; client_id/client_secret exchange for a 30-minute Bearer token). Refreshes 60s before expiry (`kRefreshMarginSecs`). **Credentials are loaded once at construction from `<repo-root>/opensky.ini`** via `QSettings` — `/opensky.ini` is gitignored (see `.gitignore`) and must be created locally by copying `opensky.ini.example`. **That example file is referenced in three places (`.gitignore`'s comment, `OpenSkyTokenManager.cpp`'s warning text, and the plan doc) but does not currently exist anywhere in the repo** — creating it (a two-line `[opensky]` / `client_id=` / `client_secret=` INI stub, no real secrets) is a real gap, not a false alarm. Without a valid `opensky.ini`, `hasCredentials()` stays false, `ensureToken()` fails fast with a `tokenError()` instead of attempting a doomed request, and the ATD page still renders (map + crosshair + zoom) with simply zero aircraft — this is non-fatal by design.
- **`Aircraft`** — `Q_GADGET` (not `QObject`) plain value type: `icao`/`callsign`/`latitude`/`longitude`/`heading`/`altitude`/`groundSpeed`/`verticalSpeed`/`lastUpdate`/`onGround`, field names matching OpenSky's REST docs directly. `Q_GADGET` over `QObject` because these are copied around in bulk inside a `QVector` every refresh, not long-lived identity-bearing objects — no need to pay for parent/child ownership or signal machinery per instance.
- **`AircraftListModel : QAbstractListModel`** — exists specifically so `upsert(QVector<Aircraft>)` can update existing rows *in place* (matched by `icao`, never by row position) with a targeted `dataChanged`, insert genuinely new aircraft, and remove ones no longer present — instead of a `QVariantList`-style full teardown/rebuild every ~30s, which would destroy and recreate every on-screen `MapQuickItem` on each refresh and make Phase 5's future smooth-motion animation impossible (you can't animate a delegate that was just destroyed and replaced).
- **`GeoBoundingBox`** — pure coordinate math (`fromCenterRadius(lat, lon, radiusKm)` → `lamin/lamax/lomin/lomax`), a flat-earth approximation deliberately not exact enough for navigation, only for "nearby traffic" queries. No Qt Location types, no networking, kept as its own tiny struct so this arithmetic has exactly one place to live.

**Control layout** (bottom-right of the page, in `AirTrafficPage.qml`): a `Column` (`controlColumn`) holding, top to bottom, the style-toggle `ZoomButton` (symbol "≡"), then "+", then "−". Tapping "≡" toggles `MapStyleMenu` open; a full-page `MouseArea` (placed *below* the column/menu in file order, so it never eats their clicks) dismisses the menu on any outside tap. **QML anchoring gotcha hit here:** the menu anchors to `controlColumn` (`anchors.right: controlColumn.left`, `anchors.top: controlColumn.top`), not to the style button itself — QML only allows anchoring to a parent or a sibling, and the style button's parent is the `Column`, not the page's root `Rectangle`, so anchoring to it directly throws "Cannot anchor to an item that isn't a parent or sibling." Aligning `top`-to-`top` with the column works because the style button is the column's first child and both it and the menu are the same 40px tall, so their vertical centers land on top of each other anyway.

**OSM tile setup — read this before touching `TrafficMap.qml`'s `Plugin` block.** Getting a plain, key-free OpenStreetMap view took several rounds of trial and error against Qt's own `osm` geoservices plugin; the working configuration (and *why* each parameter is there) is:
- `osm.mapping.cache.directory` — tile disk cache, so the map still renders from cache when offline or freshly restarted.
- `osm.mapping.providersrepository.disabled: true` — stops the plugin's *built-in* map types (Street/Satellite/Cycle/...) from doing an online "resolution" step against Qt's redirect service. This alone does **not** change which server those built-in types point at.
- `osm.mapping.host: "https://tile.openstreetmap.org/%z/%x/%y.png"` plus `osm.useragent` — per Qt's own plugin source (`qgeotiledmappingmanagerengineosm.cpp`), setting `osm.mapping.host` does **not** override the default "Street Map" type. It registers a *separate* map type named `"Custom URL Map"`, which nothing selects automatically. That custom type does have its redirection permanently disabled at construction, which is what actually avoids Qt's tile server.
- Because of the point above, `Map`'s `Component.onCompleted` in `TrafficMap.qml` scans `supportedMapTypes` for `"Custom URL Map"` and sets `activeMapType` to it explicitly. **Without this, the map silently keeps using "Street Map"**, whose primary server is Qt's own `maps-redirect.qt.io` — the exact thing that renders tiles as an "API Key Required" watermark (see [QTBUG-114118](https://bugreports.qt.io/browse/QTBUG-114118)). An earlier theory that this was zoom-level-specific (low zooms cached/fine, high zooms freshly fetched and watermarked) was a wrong guess made before reading the plugin source — the real mechanism is simply "which map type is active," independent of zoom.
- `tile.openstreetmap.org`'s usage policy is for light/dev use only. Before any real deployment, switch `osm.mapping.host` to a self-hosted tile server or a keyed provider (Thunderforest/MapTiler/etc.).

**Zoom.** `TrafficMap.zoomLevel` is the single source of truth; `Map.zoomLevel` is a one-way binding to it, smoothed by a `Behavior on zoomLevel` (`NumberAnimation`, 350ms, `OutCubic`) so the +/− buttons ease instead of snap. `zoomIn()`/`zoomOut()` must mutate `root.zoomLevel`, **not** `map.zoomLevel` directly — an earlier version did the latter, which silently deleted the `zoomLevel: root.zoomLevel` binding on the very first click (any imperative assignment to a property removes its active binding), permanently desyncing the two. Also note: unlike Qt5's `QtLocation` (which exposed pan/pinch via a `gesture: MapGestureArea` grouped property on `Map`), **Qt6's `Map` has no built-in `gesture` property at all** — panning would require explicitly adding `PinchHandler`/`DragHandler`/`WheelHandler`, which this page deliberately does not do, so the map is non-interactive by default and can't fight the location-follow center binding.

**Map styles.** "Dark" (`TrafficMap.mapStyle === "dark"`) is a flat, semi-transparent `Rectangle` tint drawn over the same standard tiles — not a second tile source, and deliberately not a shader/`Blend`-based recolor, to keep the cost near-zero on weak GPUs (Raspberry Pi Zero 2 W is an explicit target for this app). Satellite is **not implemented**: the `osm` plugin ships no free/keyless satellite backup at all (confirmed in its source — the comment there literally says none exists), so it needs either a keyed provider (Mapbox/MapTiler/Bing) or a usage-restricted free option like ESRI World Imagery, and either way a second `Plugin`+`Map` pair, since this plugin only supports one custom tile slot. `MapStyleMenu.styles` can gain a `"satellite"` entry with no layout changes once a provider is chosen.

**Not built yet (Plan Phases 5–8):** smooth marker motion (`Behavior`/`CoordinateAnimation` on position and heading — markers currently snap between ~30s updates). **Design already agreed with the user and written up in `AIR_TRAFFIC_DISPLAY_PLAN.md`'s Phase 5 section — read that before starting, it's meant to be implemented directly, not re-discussed** (dead-reckoning via a 1s `Timer` + `atDistanceAndAzimuth` in `TrafficMap.qml`'s delegate, a linear `CoordinateAnimation` `Behavior`, and a `RotationAnimation.Shortest` `Behavior` on `AircraftMarker.qml`'s rotation; a first pass was implemented and then deliberately reverted back to clean Phase 4 by request). Also still missing: the traffic-count readout (`CoordinateBar`/`StatusBar` cover the rest of Phase 6's overlay already — see the QML layer bullets above), a "Traffic Unavailable" UI element surfacing `FlightTrackerProvider.status` (the backend already tracks it and never clears the map on failure — nothing in QML displays it yet), stale-aircraft fade/remove after a timeout instead of vanishing instantly, and a dedicated performance pass beyond the `active`/`SwipeView.isCurrentItem` polling gate described above. Also missing: `opensky.ini.example` itself (see the `OpenSkyTokenManager` bullet above) and satellite map style (see Map styles above).
